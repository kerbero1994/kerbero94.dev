Work / Accessibility on sitimm.org

Accessibility case · sitimm.org · 2026

Making accessibility hard to break.

sitimm.org serves a union of 70,000 members in 8 languages. This is what failed, the WCAG criterion behind each failure, how it was fixed, and the checks that keep it fixed.

My role
The target, the rules and the review. AI agents wrote the fixes; a second model reviewed them.
Target
WCAG 2.2 AA
Checks
30 lint rules and one of my own, typed components, keyboard tests, axe on six flows in light and dark
Languages

Why this one

At Drift I owned accessibility for three years and did most of it by hand. At SITIMM the job changed: I'm one engineer directing AI agents, and I can't read every line they write. So the work became making the wrong thing hard to ship.

What keeps it fixed

  1. Lint30 accessibility rules run on the whole repo before every push, plus one I wrote after the scan below: the brand red can't be used as a text colour.
  2. TypesA dialog can't be built without a name. The compiler says no before a reviewer has to.
  3. Keyboard testsEach picker is tested for Tab, arrows, wrapping and Space. Sign-up runs end to end with the keyboard only.
  4. axeA test loads six flows in a real browser, in light mode and again in dark, and fails on any serious or critical violation. It runs before every push that changes the interface. Its list of exceptions is empty.
  5. One focus ringEvery interactive element shares one visible focus style, shown to keyboard users.

Then I scanned production

For this page I scanned production myself, on 20 and 21 November 2026: 27 public pages, in light and dark mode, with axe-core and the WCAG 2.0 to 2.2 rules, levels A and AA. I expected a clean report. I didn't get one.

Why nothing caught it. The list above describes the test as the pull request leaves it. The day I scanned, it only ran in light mode, on four flows, and only in CI. CI had been off since September. When I ran it by hand it could not even start: the browser it needed was not installed. Had it started, it would have failed on a rule that a dependency update had added. The check was easy to break, and it had broken without a sound.

What I changed. One pull request, the next day. It is in review: sitimm.org gets these fixes when it merges.

  • One cause, fixed once. Red text now uses a colour token that changes with the theme. That was 140 uses in 65 files, and the lint rule keeps the old one out.
  • Cards. A card that was one big link now has its link on the title, stretched over the card. A card that was one big button is now a box with a button over it, so the heading inside is a real heading again.
  • The test. Six flows, both themes. It waits for the theme and the cookie banner before it measures, because both arrive after the page loads. It adds about a minute to a push.
  • Proof that it works. I put three of the old failures back. The six dark checks failed, on 1, 4 and 7 elements. The six light checks passed, which is exactly why the old test never saw them.

On the pull request's preview build, the same 27 pages come back clean in both themes: no violations, one top-level heading per page, no skipped levels.

I changed my mind about the “404”. The page shows a giant, pale “404” above the real message. In the first draft of this page I defended it as decoration, exempt from contrast. Then I made it readable. Hiding something from a screen reader doesn't hide it from a person with low vision.

Left for a person. axe could not measure text over gradients and photos, between 54 and 182 elements per page. Those need checking by eye and with a contrast picker.

What automated checks can't tell me

  • They find about half. The rest needs a keyboard, a screen reader and time. The focus lost after signing in was caught in review, on the third pass. No scanner flags that.
  • A scanner is a version. The same pages passed one release of axe and failed the next. A clean report says which rules ran, not that the page is accessible.
  • Not verified yet: the map of union offices and the magazine's PDF reader.
  • Next: the test covers six flows. The other 21 pages were clean in the scan, and nothing but the lint rule keeps them that way.
